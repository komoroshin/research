# Сборка питч-артефактов

Вторая стадия каскада **idea-check → pitch-build → hypothesis-iteration**.
Вход — паспорт гипотезы из стадии idea-check (или его эквивалент: любой
документ с проверенными числами и источниками). Выход — комплект
артефактов, готовый к первому показу, и дополненный паспорт.

Если паспорта нет — не начинай сборку на пустых числах: либо предложи
пройти стадию проверки идеи (скилл `idea-check`), либо собери с
пользователем мини-паспорт из того, что уже известно, честно пометив
непроверенное как допущения.

## 1. Скелет деки — от вопросов инвестора

Дека — не рассказ о продукте, а заготовленные ответы. Инвестор задаст
предсказуемые вопросы; каждый слайд существует, чтобы ответить на один из
них. Опорный скелет (адаптируй порядок и состав под проект, но проверь,
что каждый вопрос закрыт):

| Вопрос инвестора | Слайд(ы) |
|---|---|
| Какая проблема и сколько она стоит? | проблема: масштаб (люди) + цена (деньги/время, прямые и непрямые) |
| Что вы делаете и чем это отличается? | решение + позиционирование (что продукт НЕ является — тоже сюда) |
| Насколько велик рынок? | TAM/SAM/SOM |
| Кто ещё это делает? | конкурентная карта + уникальность, вынесенная явно (рамкой/акцентом), а не размазанная |
| Почему сейчас? | окно: технология, регуляторика, поведение |
| Как зарабатываете? | модель + юнит-экономика |
| Чем это кончится для меня? | сделки-аналоги и возврат |
| Что может всё сломать? | регуляторика + риски (честные, с контрмерами) |
| Кто вы? | команда |
| Что просите? | ask, разбитый на этапы, с дешёвым первым шагом |

Правила, которые делают деку живучей:

- **Число → источник.** У каждого числа сноска, источник в приложении или
  заметках. Число без источника — вопрос, на который на показе никто не
  ответит.
- **Допущение → слово «допущение» на слайде.** Явное допущение выглядит
  честно; вскрытое инвестором — как обман.
- **SOM — арифметика, не доля.** SOM = одобренный бюджет теста ÷ ожидаемый
  CAC = измеримое число покупателей. «1% рынка» — не SOM.
- **Сделки-аналоги — полными строками**: покупатель, актив, год, параметры
  (сумма или мультипликатор), что именно покупали, источник. Отдельно —
  провальные сделки категории: их найдёт и инвестор, лучше самим назвать
  и объяснить.
- **Ask с первым дешёвым шагом.** Просить весь бюджет одним куском —
  просить веру; просить маленький первый шаг с измеримым выходом —
  просить эксперимент. Второе одобряют чаще.
- **Уникальность — выпятить.** Если ответ на вопрос «в чём уникальность»
  существует, но инвестор его всё равно задал — ответ не считывается;
  выноси его отдельной рамкой/меткой на конкурентной карте.

## 2. Проверки

Дека будет переписываться много раз (стадия итераций впереди), поэтому
проверки окупаются с первого дня. Собери минимальный набор скриптов —
даже простых:

- **сверка чисел**: числа деки совпадают с паспортом/исследованием;
- **запрещённые формулировки**: список регулярок для снятых обещаний и
  опасных фраз (медицинские/юридические обещания, «гарантируем», всё, что
  снято решением автора);
- **утечка внутреннего**: заметки спикера и внутренние слайды не попадают
  в публичную копию (проверка маркерной фразой);
- **вёрстка**: для HTML/визуальных дек — проверка переполнения текста на
  реальном рендере.

Каждую регрессию, пойманную скриптом, инвестор не увидит. Пути к скриптам
и команду запуска запиши в паспорт.

## 3. Зеркальные артефакты

- **Финмодель-отправная точка**: константы из деки (цены, бюджеты, CAC),
  рычаги помечены как допущения, 2–3 сценария (оптимистичный / базовый /
  консервативный), потребность в капитале, сверка с ask. Простая честная
  модель убедительнее фальшиво-точной: у ранней стадии куча неизвестных,
  и модель должна показывать, ЧТО тест призван узнать.
- **Письмо/сопроводительный текст** — если показ идёт перепиской: та же
  структура, что вопросы адресата, с номерами слайдов.
- **Выгрузки** (текст для дизайнера, экспорт) — скриптом из единого
  источника, не руками: ручная копия отстанет после второй правки.

## 4. Закрытие стадии

Дополни паспорт гипотезы: пути к артефактам, набор проверок и команды
запуска, процесс публикации, список зеркальных артефактов. Заверши
словами: артефакты готовы к показу; когда придёт фидбек стейкхолдера —
следующая стадия, итерация по фидбеку (скилл `hypothesis-iteration`).

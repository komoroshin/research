# Задание Клод Дизайну — экраны прототипа Threshold

## Контекст

Threshold — приложение, которое за месяц наблюдения находит, какая
группа продуктов совпадает с плохими днями человека, и предлагает
проверить это за восемь дней. Ответ — не «нельзя», а «сколько». Ты уже
делал деку Threshold и знаешь визуальный язык — экраны должны быть с ней
одной семьи, но это интерфейс, а не слайды: плотнее, тише, без
презентационных заголовков.

Аудитория экранов — взрослые в США с симптомами по типу СРК, которые уже
пробовали диеты и устали от запретов. Главное чувство, которое экраны
должны оставлять: «меня не ограничивают, за мной наблюдают и мне честно
говорят, что нашли».

## Что нужно

Девять экранов плюс два подэкрана и служебный, каждый в нужных
состояниях, для iPhone (391 × 852, safe area). Светлая тема. Один язык на
макетах — английский; русские строки есть в `04-teksty.md`, длина текста
на них на 20–30% больше — закладывать запас.

Результат — макеты в Клод Дизайне для сборки в SwiftUI: компоненты
системные (списки, кнопки, сегменты, ползунки), поверх — типографика,
цвет и композиция бренда. Никаких кастомных контролов, которые нельзя
собрать за час.

Все тексты — из `04-teksty.md` дословно, по ключам. Не переписывать.

## Принципы

1. **Одно действие на экран.** На каждом экране ровно одна главная кнопка;
   исключение — Э4, где три кнопки нарочно равны.
2. **Числа крупно, объяснения мелко.** «12 из 15», «60%», «125 мл» — это
   и есть контент; текст вокруг них — подпись.
3. **Ничего красного для симптомов.** Плохой день, отбракованный день,
   «не подтвердилось» — нейтральные тона. Красный только на Э8.
4. **Язык возврата.** Иконки и иллюстрации без запретительных знаков:
   никаких перечёркнутых продуктов, замков, крестов.
5. **Спокойно.** Без конфетти, без «поздравляем», без прогресс-баров с
   процентами достижений. Прогресс — шкала дней, и всё.

## Экраны

### Э0 · Вход
Один экран без прокрутки. Заголовок-обещание крупно (`onb.title`). Три
вопроса сегментными контролами, каждый с подписью. Кнопка Health —
вторичная, кнопка «Начать» — главная. Дисклеймер внизу мелко, но
читаемо. Состояния: Health разрешён (зелёная галочка у кнопки) /
отклонён (нейтральная пометка «демо-данные»).

### Э1 · Карта дня
Вечерний экран, 30 секунд. Три ползунка с текстовыми якорями по краям,
без цифр посередине. Строка фона под ползунками — тихая, серая: сон, шаги,
пульс, источник. Два переключателя (алкоголь, болел) и отдельный —
«кровь в стуле» — визуально отделён и не выглядит как обычный
переключатель. Кнопка «Добавить еду» вторичная, «Закрыть день» главная.
Состояния: пусто / частично / закрыт (подтверждение).

### Э1а · Добавить еду
Три крупные плитки: фото, голос, текст. После выбора — карточка
распознанного блюда с группами как тихими тегами и строкой «это ваша
проба на сегодня — засчитано», если в проверке. Кнопки «Верно» /
«Исправить».

### Э2 · Первый вывод
Карточка внутри Today. Заголовок, одно предложение-наблюдение, и
обязательно подпись «пока наблюдение, не вывод» — не мельче основного
текста более чем на одну ступень. Кнопка «Понятно».

### Э3 · Фон — главный экран
Самое крупное на экране — процент уверенности. Под ним — «ещё около N
дней». Три мини-показателя «N из M» в ряд. Ниже — блок «Спросить» с тремя
вопросами как тихими чипами; по нажатию раскрывается ответ. Кнопка
«Закрыть день». Состояние: 60% (заготовка).

### Э4 · Подозрение — центральный экран
Полноэкранный модальный. Метка сверху («Подозрение»). Текст с числами: 12
из 15 и 3 из 20 должны читаться как числа, остальное — как речь. Абзац
«может оказаться совпадением» — не мельче основного. **Три кнопки
одинакового размера и веса**, вертикально: «Проверим», «Не сейчас»,
«Другой подозреваемый». Ни одна не главная. Это единственный экран, где
правило одной кнопки нарушается намеренно.

### Э5 · Проверка
Шапка: группа, день, фаза. Шкала дней горизонтально — точки: пройден,
отбракован (другая форма, не цвет ошибки), сегодня (акцент), впереди.
Карточка задачи дня: в ограничении — текст и три замены списком «из
вашего рациона»; в возврате — доза крупно (малая / средняя / полная).
Состояния: обычный день; день отбракован — карточка с причиной и строкой
«доза переносится», без красного; пауза — «вчера без записей, проверка на
паузе, не провалена».

### Э6 · Ответ
Модальный. Одна строка крупно — самая крупная типографика в приложении:
«Milk: up to 125 ml is fine, 250 ml brings symptoms». Под ней — как
считали, мелко. Кнопка «Следующий подозреваемый: фруктаны» главная,
ссылка «В карту» текстом. Второе состояние: «Не подтвердилось» — тот же
размер, тот же нейтральный цвет, подпись «молочное можно вернуть».
Никаких визуальных признаков неудачи.

### Э7 · Карта
Шесть строк по группам. Проверенная — с порогом текстом; остальные —
«в наблюдении» тихо. Кнопка «Страница для врача». Состояние «пусто»:
все шесть в наблюдении и одна строка «первый ответ появится после
первой проверки».

### Э7а · Страница для врача
Документ, а не экран приложения: белый лист, чёрный текст, структура
как в выписке — протокол, результаты, динамика тремя числами. Подвал
«наблюдения участника, не диагноз и не назначение». Кнопка «Поделиться».
Этот экран должен хорошо выглядеть распечатанным.

### Э8 · Красный флаг
Единственный экран с красным акцентом. Заголовок «Протокол на паузе»,
текст с причиной, одна кнопка «Открыть страницу для врача». Нет кнопки
закрытия, нет «продолжить», нет крестика.

### Служебный · Переключатель момента
Утилитарный список из десяти пунктов. На экране активного момента —
тонкая плашка сверху с названием момента, чтобы показывающий видел, где
он. Не стилизовать.

## Что сдать

- Макеты всех экранов и состояний в одном файле, названные по ключам
  (`onboarding`, `dayCard`, `suspicion`…).
- Цвета, шрифты, отступы — одним списком токенов для SwiftUI.
- Иконки — только системные SF Symbols, перечнем.

## Чего не делать

Не рисовать онбординг-карусель, paywall, экран регистрации, тёмную тему,
иллюстрации еды, иконки продуктов. Не менять тексты. Не добавлять
экраны, которых нет в списке.

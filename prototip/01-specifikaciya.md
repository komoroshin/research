# Спецификация прототипа Threshold — уровень A

Версия 1, 5 сентября 2026. Источник решений: `../prototip-brif.md`,
`../mashina-gipotez-spec.md`. Пакет: `00-README.md` — состав,
`02-scenarii.md` — сценарии, `03-tz-dizajn.md` — задание дизайну,
`04-teksty.md` — все строки RU/EN, `05-priemka.md` — критерии приёмки и
прогон.

## 1. Цель и границы

**Цель.** Дать в руки один полный оборот продукта — подозрение → проверка →
ответ — так, чтобы человек без объяснений понял, что делает приложение и
чем оно отличается от трекера. Прототип отвечает на вопрос «понятно ли и
хочется ли», не на вопрос «работает ли математика».

**Входит.** Девять экранов и служебный переключатель момента. Живая
навигация, живые тексты, заготовленные данные. Health — живой, если CTO
подключает (интеграция есть); иначе — заготовленные значения с пометкой.

**Не входит.** Машина гипотез (только её результат), оплата и paywall,
регистрация и аккаунты, серверная часть, push-уведомления, библиотека
протоколов, ресторанные режимы, ассистент как свободный чат.

**Платформа.** iOS, SwiftUI, iPhone; минимальная версия — та, что стоит на
телефонах команды и Олега (уточнить у CTO, ориентир iOS 17). Оффлайн:
всё локально, сеть не нужна. Сборка — TestFlight или прямая установка.

**Язык.** Английский основной, русский переключаемый. Все строки — из
`04-teksty.md`, в коде — одним файлом локализации, без строк в разметке.

## 2. Модель данных прототипа

Данные локальные, заготовлены в одном JSON-файле, загружаются при старте.
Переключатель момента подменяет набор целиком.

```
Person        { name, language }
Day           { date, belly 0–5, stool 0–5, heavy 0–5,
                sleepMin, steps, restingHR,
                meals: [Meal], alcohol: bool, illness: bool,
                status: good | bad | neutral | discarded,
                discardReason?: shortSleep | alcohol | illness }
Meal          { time, source: photo | voice | text, dishName, groups: [Group] }
Group         fructans | gos | lactose | fructose | sorbitol | mannitol
Suspicion     { group, badWith, badTotal, goodWith, goodTotal }
Check         { group, startDate, phase: restriction | return,
                dayIndex, doseStep 1–3, placeboDayIndex (скрыт),
                discardedDays: [date], status: active | paused | done }
Verdict       { group, result: threshold | notConfirmed, thresholdText }
MapEntry      { group, status: checked | observing, thresholdText? }
Confidence    { fullDays, badDays, goodDays, percent, daysLeft }
Moment        day0 | day7 | background | suspicion | check3 |
              check6discarded | verdict | verdictNotConfirmed | map | redFlag
```

Заготовленный подозреваемый: лактоза, 12 из 15 плохих, 3 из 20 хороших.
Заготовленный вердикт: «до 125 мл переносится, 250 мл даёт симптомы».
Второй вердикт (переключатель): «не подтвердилось».

## 3. Навигация

Таб-бар из трёх вкладок: **Today** (Э1/Э3/Э5 в зависимости от момента),
**Map** (Э7), **Ask** (ассистент, заглушка). Вход (Э0) — один раз при
первом запуске, дальше не показывается. Подозрение (Э4), ответ (Э6) и
красный флаг (Э8) — модальные экраны поверх Today. Первый вывод (Э2) —
карточка внутри Today в момент day7.

Переключатель момента — скрытый: пять быстрых нажатий на заголовок Today
или пункт в настройках. Показывает список моментов; выбор подменяет
данные и открывает соответствующий экран.

## 4. Экраны

Для каждого: назначение, элементы сверху вниз, действия и переходы,
состояния, данные. Тексты — по ключам из `04-teksty.md`.

### Э0. Вход · `onboarding`

Назначение: снять ожидание запретов и получить разрешение Health.
Элементы: заголовок `onb.title`; три вопроса одним экраном — сегментные
контролы: что беспокоит (`onb.q1` + три варианта), как часто (`onb.q2` +
три варианта), что пробовали (`onb.q3` + три варианта); кнопка
`onb.health` → системный запрос HealthKit (сон, шаги, пульс покоя); кнопка
`onb.start`; подпись `onb.disclaimer` мелко.
Переходы: `onb.start` → Today в моменте day0. Если Health отклонён —
продолжаем, Today показывает заготовленные значения с пометкой
`common.demoData`.
Состояния: разрешение выдано / отклонено / не запрошено.

### Э1. Карта дня · `dayCard`

Назначение: 30-секундный вечерний ввод. Открывается из Today кнопкой
`today.closeDay` или сама после 20:00 (в прототипе — кнопкой).
Элементы: заголовок `day.title` с датой; три ползунка 0–5 с подписями
`day.belly`, `day.stool`, `day.heavy`, каждая с текстовыми якорями крайних
значений (`day.scale0`, `day.scale5`); строка фона `day.background` с
подстановками: сон, шаги, пульс, источник (Health или демо); две
переключалки `day.alcohol`, `day.illness`; кнопка `day.addMeal` → Э1а;
кнопка `day.close`.
Переходы: `day.close` → Today с подтверждением `day.closed`; если момент
check* — ответ проверки (`check.dayResult`); если отмечена кровь в
`day.stool` через отдельный переключатель `day.blood` → Э8 немедленно.
Состояния: пусто / частично / закрыт.

### Э1а. Добавить еду · `addMeal`

Элементы: три кнопки `meal.photo`, `meal.voice`, `meal.text`; после
выбора — карточка распознанного: `meal.recognized` с названием блюда и
группами (`group.*`), строка `meal.isProbe` если в проверке; кнопки
`meal.confirm` / `meal.fix`.
Данные: если CTO подключает живое распознавание — оно; иначе выбор из
пяти заготовленных блюд (`meal.preset1..5`). Голос — системная диктовка
или заглушка.
Переход: назад в Э1 со строкой «записано».

### Э2. Первый вывод · `firstInsight`

Назначение: обещанный седьмой день. Карточка в Today в моменте day7.
Элементы: заголовок `insight.title`; текст `insight.body` (про сон);
подпись `insight.caveat` («пока наблюдение, не вывод»); кнопка
`insight.ok`.
Правило: это наблюдение, не подозрение — формулировка обязана содержать
`insight.caveat`.

### Э3. Фон · `background`

Назначение: главный экран дней 7–30. Показывает, что идёт накопление.
Элементы: крупно процент уверенности `bg.confidence` с подстановкой;
подпись `bg.daysLeft`; три мини-показателя `bg.fullDays`, `bg.badDays`,
`bg.goodDays` как «N из M»; кнопка `today.closeDay`; блок `bg.ask` с тремя
заготовленными вопросами (`ask.q1..3`) — по нажатию раскрывается готовый
ответ (`ask.a1..3`).
Данные: Confidence из заготовки; в моменте background — 60%.

### Э4. Подозрение · `suspicion`

Назначение: центральный экран. Модальный, полноэкранный, закрыть свайпом
нельзя — только кнопкой.
Элементы: метка `susp.label`; текст `susp.body` с подстановками
(badWith/badTotal/goodWith/goodTotal, группа); абзац `susp.caveat`
(«может оказаться совпадением»); три кнопки **равного веса**:
`susp.check`, `susp.notNow`, `susp.other`.
Переходы: `susp.check` → Э5 в моменте check1 (день 1 ограничения);
`susp.notNow` → Э3 с тостом `susp.willReturn`; `susp.other` → список из
одной альтернативы (`group.fructans`, с числами послабее) → выбор →
Э4 с новой группой.
Запрещено: любые слова «нельзя», «уберите», «диагноз».

### Э5. Проверка · `check`

Назначение: день N проверки. Замещает Today на время проверки.
Элементы: шапка `check.header` (группа, день, фаза); карточка задачи дня:
в ограничении — `check.restrictionTask` + список замен `check.swaps`
(три заготовленных, «из вашего рациона»); в возврате —
`check.returnTask` с дозой (`dose.small/medium/full`); шкала дней с
отметками: пройден / отбракован / сегодня / впереди; кнопка
`today.closeDay` → Э1.
Состояния (моменты): check3 — ограничение, день 3; check6discarded —
день отбракован: вместо задачи карточка `check.discarded` с причиной
(`discard.shortSleep`, подстановка сна) и строкой `check.moved`; также
состояние паузы `check.paused` (вчера без записей).
Правило длины: адаптивное (спецификация машины); в прототипе — параметр
`restrictionMinDays=5`, `restrictionMaxDays=14`, `calmDaysNeeded=3`;
переход в возврат в прототипе — по переключателю момента.
Контрольный день: `placeboDayIndex` существует в данных, на экране никак
не отмечен.

### Э6. Ответ · `verdict`

Назначение: одна строка. Модальный.
Элементы: метка `verdict.label`; крупно `verdict.threshold` с подстановкой
(группа, малая доза, полная доза); подпись `verdict.how` (про личный
разброс и контрольный день); кнопка `verdict.next` (следующий подозреваемый,
группа подставляется); ссылка `verdict.toMap`.
Второе состояние: `verdict.notConfirmed` + `verdict.notConfirmedWhy` +
та же кнопка `verdict.next`.
Правило: «не подтвердилось» подаётся как снятое ограничение, тон
нейтрально-положительный.

### Э7. Карта · `map`

Назначение: накопленный актив. Вкладка Map.
Элементы: заголовок `map.title`; шесть строк по группам: название
(`group.*`), статус `map.checked` с порогом или `map.observing`; кнопка
`map.doctorPage` → Э7а.
Состояния: до первого вердикта — все шесть `map.observing` и подпись
`map.empty`; после — лактоза `map.checked`.

### Э7а. Страница для врача · `doctorPage`

Элементы: заголовок `doc.title`; блоки: `doc.protocol` (что и когда
проверяли), `doc.results` (по группам), `doc.symptoms` (динамика — три
числа: медиана до, во время, после); подвал `doc.disclaimer`; кнопка
`doc.share` — системный share sheet с текстом страницы.

### Э8. Красный флаг · `redFlag`

Назначение: остановка. Модальный, без закрытия свайпом.
Элементы: заголовок `red.title`; текст `red.body` с подстановкой
причины (`red.blood`, `red.weightLoss`, `red.night`, `red.onset50`);
единственная кнопка `red.doctorPage` → Э7а. Кнопки «продолжить» нет.
Переход назад — только через переключатель момента (служебный).
Триггер в прототипе: переключатель `day.blood` в Э1 или момент redFlag.

### Служебный. Переключатель момента · `momentSwitcher`

Список из десяти моментов (раздел 2). Выбор — подмена данных и переход
на целевой экран. Доступ: пять нажатий на заголовок Today. На экране
момента — плашка `common.demoMoment` с названием, чтобы показывающий
видел, где он.

## 5. Health

Запрос при входе: сон (asleep), шаги, пульс покоя, чтение. Использование:
строка фона в Э1 и Э3, причина отбраковки в Э5. Если разрешение отклонено
или данных нет — заготовленные значения, подпись `common.demoData`.
Отбраковка по живому сну: порог 6 часов; в момент check6discarded
переключатель принудительно подставляет 4 ч 40 мин независимо от Health —
иначе на стенде экран не показать.

## 6. Правила поведения, которые нельзя нарушить

1. Ни на одном экране нет слов «нельзя», «уберите», «диагноз», «лечит»,
   «вы пропустили», «серия». Проверяется грепом по файлу строк.
2. Три кнопки на Э4 одинакового размера и веса.
3. Из Э8 нет пути «продолжить».
4. «Не подтвердилось» — не красный, не ошибка.
5. Контрольный день не виден нигде, кроме данных.
6. Все строки — из файла локализации; строк в разметке нет.

уверенности; аккаунты; тёмная тема; iPad; Android.

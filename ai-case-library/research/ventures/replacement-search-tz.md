# ТЗ: поиск третьей продуктовой ставки взамен закрытой

Дата: 01.09.2026. Заказчик: Константин Морошин, «Океан Тех».
Исполнитель: агент-оркестратор с правом запускать субагентов.
Репозиторий: `komoroshin/research`. Документ самодостаточен: вся нужная
фактура лежит в файлах, перечисленных в разделе 3.

## 1. Задача и результат

01.09.2026 по итогам проверки закрыта одна из трёх продуктовых ставок
портфеля — голосовой компаньон для пожилых (вердикт и основания:
`elder-companion-passport.md`). В деке совместного предприятия
(`jv-pitch-skeleton.md`, слайд 7) образовалась дыра.

Задача — найти кандидата на замену по воронке «сначала фильтры, потом
ресёрч» и довести одного финалиста до паспорта гипотезы.

Результат — ровно один из двух исходов, оба считаются успехом:

- **(а)** паспорт гипотезы по новому кандидату с вердиктом «развивать»;
- **(б)** обоснованный вывод «замены нет, дека держится на двух ставках» —
  с таблицей, почему каждый кандидат срезан.

Натянутый третий продукт хуже, чем его отсутствие. Подгонять кандидата
под желаемый вердикт запрещено.

## 2. Контекст (сухой остаток)

**Кто мы.** Студия исследований и разработки ИИ (Москва), выходящая на
международный рынок. РФ — полигон обкатки, продукт на РФ не строим.

**Работающие активы** (статусы проверены 31.08.2026, см.
`00-common-context.md`; построенное и спроектированное называть разными
словами — железное правило):
- полнодуплексный голосовой диалог ~1 с с перебиваниями — работает;
- долгая память о человеке между сессиями — работает;
- локальный/офлайн-инференс (данные не покидают контур) — работает;
- удержание персоны + модель-судья — условный актив, возникает при
  контракте с Анимаккорд (~$1M, в переговорах);
- нетехнологические: база 277 верифицированных AI-кейсов с метриками,
  методология двухнедельного исследования с оценкой эффекта.

**Портфельная рамка.** Дека СП продаёт «три применения одних наработок» —
портфель с общим голосовым ядром. Действующие ставки: QA/сертификация
голосовых агентов (главная) и приоритизация проверок учёта в энергосетях.
Кандидат на замену обязан усиливать эту историю, а не размывать её.

**Почему умер компаньон** (полностью — в паспорте): позиция занята
(девять продуктов продают ту же связку), речевые маркеры с алертом дают
класс IIa по MDR и статус изделия по FDA, канал закрыт для российской
команды юридически, несущее допущение о ежедневной вовлечённости не
подтвердилось независимыми данными. Урок методики: концепт и питч писались
ДО проверки и ушли в корзину. В этом ТЗ порядок обратный.

## 4. Шаг 0 — фильтры-убийцы (закон отбора)

Шесть бинарных фильтров, выведенных из паспорта. Кандидат проверяется по
всем шести ДО какого-либо веб-ресёрча — только на знаниях и локальных
файлах. Не прошёл один фильтр — срезан, причина фиксируется одной строкой.

| # | Фильтр | Проходит, если | Почему фильтр существует |
|---|---|---|---|
| Ф1 | Обязанный плательщик | До ресёрча можно назвать, кто платит и какая строка бюджета его обязывает (P&L-эффект, регуляторное требование, страховое возмещение) | Компаньонство умерло без обязанной строки; выжившие продают эффект в P&L |
| Ф2 | Правовой допуск команды | Не биометрия/данные о здоровье физлиц США в объёмах порогов DOJ DSP (голос — 1 000 чел., здоровье — 10 000); не госзакупки ЕС (ст. 5k Рег. 833/2014); B2B с данными в периметре клиента проходит автоматически | Отказ приходит на legal review, до пилота. Локальный инференс здесь — пропуск, а не фича |
| Ф3 | Без клинической претензии | Продукт не мониторит/не предсказывает болезнь или её риск (MDR ст. 2(1) — мониторинг и предсказание дают медназначение сами по себе; CDS-гайденс FDA ред. 29.01.2026) | Kintsugi: $16M и 4 года на регуляторику, заявка не подана, компания закрыта 02.2026 |
| Ф4 | Без добровольной вовлечённости | Ценность продукта не требует, чтобы конечный пользователь по своей воле пользовался им ежедневно | Независимые данные: 77% падение использования компаньонов за 5 дней; архитектура Sensi (не требует участия) собрала больше денег, чем ElliQ за 9 лет |
| Ф5 | Сидит на наших активах | Использует минимум два из трёх работающих активов (дуплекс, память, локальный инференс). Осознанное ослабление: сидит на методологии исследования — допустимо, но помечается «вторая история» и требует отдельного решения заказчика | Иначе это не переиспользование, а новый стартап, и рушится логика деки «три применения одного ядра» |
| Ф6 | Категория жива и не братская могила | Есть раунды аналогов 2024–2026 ИЛИ ≥2 кейса в нашей базе с измеренным эффектом; на шаге 0 — по памяти и базе, некролог добирается на шаге 2 | AgeTech: −72% финансирования г/г; категории умирают целиком и с одинаковой причиной |

Пограничные случаи трактуются против кандидата: сомнение по фильтру —
это «не прошёл», а не «уточним потом».

## 5. Этапы работы

### Шаг 1 — генерация из данных (без веб-ресёрча)

Три источника, в этом порядке:

1. **Майнинг собственной базы.** Прогнать `cases.json` и `small-cases.json`
   скриптом: отобрать кейсы, где голосовой/диалоговый AI покупается B2B с
   измеренным эффектом; кластеризовать по покупателю, отрасли, бюджету.
   Каждый кластер с ≥2 кейсами — кандидат.
2. **Вторичная руда из `elder-companion-checks/`.** Отчёты называют живые
   бюджеты рядом с умершей идеей (голосовые агенты для клиник и страховых,
   value-based care, P&L-продукты для операторов, supplemental-бенефиты).
   Выписать всё, что там куплено деньгами, и превратить в кандидатов.
3. **Пятёрка отвергнутых** из лонг-листа — ре-проверка по новым фильтрам.

Выход: **10–15 кандидатов**, каждый — карточкой по разделу 6, каждый
прогнан через Ф1–Ф6 с построчным вердиктом. Ожидаемый остаток: 3–4.

Файл: `ventures/replacement-search/shortlist.md`. Коммит по завершении шага.

### Шаг 2 — дешёвый скрининг выживших

По одному субагенту на кандидата, параллельно. Бриф каждому — только
**два самых смертельных вопроса для этого кандидата** (выбирает
оркестратор; типовые пары: «плательщик + некролог» или «занятость позиции
+ допуск»). Обязательная дисциплина брифа:

- искать и подтверждения, и опровержения — опровержения ценнее;
- каждое число — источник (название, год, ссылка); вендорские цифры
  помечать отдельно от независимых;
- всё, что допущение, — словом «допущение»;
- бюджет: ≤40 обращений к сети на агента; отчёт сохранять по ходу работы,
  а не в конце (защита от обрыва);
- файл: `ventures/replacement-search/screen-NN-<candidate>.md`.

Выход: вердикт «в финал / срезан» по каждому, остаток **1–2 финалиста**.

### Шаг 3 — полный idea-check по финалисту

Запустить скилл `idea-check` по одному финалисту (при двух — по тому,
что сильнее по Ф1; второй остаётся в резерве и НЕ проверяется, пока жив
первый). Гипотеза и критерии фальсификации показываются заказчику до
запуска исследования — это гейт, его не перепрыгивать. Выход — паспорт
`ventures/<candidate>-passport.md` с вердиктом.

При вердикте «развивать» — стоп: `pitch-build` и правка деки запускаются
только решением заказчика. При «изменить» — один цикл уточнения и
повторная проверка изменённой части, не более. При «закрыть» — переход к
резервному финалисту, если он есть; если нет — исход (б) из раздела 1.

## 6. Формат карточки кандидата (шаг 1)

```
### K-NN. <Название кандидата>
Продукт X для аудитории Y решает проблему Z способом W.
Платит <кто>, потому что <обязанная строка бюджета>.
Опора на активы: <дуплекс / память / локальный инференс / методология>.
Доказательства из базы: <id кейсов> либо «аналоги: <компания, раунд, год>».
Фильтры: Ф1 ✓/✗ <строка> · Ф2 ✓/✗ <строка> · … · Ф6 ✓/✗ <строка>
Вердикт шага 1: в скрининг / срезан (<номер фильтра>).
```

## 7. Приёмка

Работа принимается, если:

1. Все 10–15 кандидатов оформлены карточками, у каждого — построчные
   вердикты по шести фильтрам. Срезанные не выброшены, а лежат в
   `shortlist.md` с причиной — это половина ценности документа.
2. Каждое число в отчётах шагов 2–3 имеет источник с годом; вендорские
   и независимые цифры различены; допущения помечены.
3. По каждому скринингованному кандидату есть некролог ниши или явная
   запись «закрытий не найдено, искали там-то».
4. Финалист либо доведён до паспорта, либо честно срезан; исход (б)
   оформлен таблицей причин, а не одной фразой.
5. Ни один концепт и ни один питч не написан до паспорта.
6. Все файлы — в `ventures/replacement-search/`, тексты по `textstyle.md`,
   имена файлов латиницей, валюта $. Коммиты — после каждого шага, пуш в
   рабочую ветку сессии.

## 8. Чего не делать

- Не строить концепт, питч, лендинг, деку — ничего продуктового — до
  паспорта с вердиктом «развивать».
- Не воскрешать компаньона для пожилых в исходной формулировке; заход в
  уход за пожилыми допустим только как новый кандидат через все фильтры.
- Не ослаблять фильтры под симпатичного кандидата; ослабление Ф5 (см.
  таблицу) — единственное допустимое и только с пометкой.
- Не тратить веб-бюджет на шаге 0–1: генерация идёт из локальных файлов.
- Не выносить решения за заказчика: выбор финалиста при двух равных,
  запуск pitch-build и правка деки — его решения, ТЗ лишь готовит их.
- Не смягчать вердикты. «Развивать с оговорками» при непройденном
  фильтре — это «срезан».

## 9. Ориентир по трудоёмкости

Шаг 0–1 — один заход оркестратора, без субагентов. Шаг 2 — 3–4 субагента
параллельно, порядка часа. Шаг 3 — полный idea-check, 6 субагентов,
1–2 часа с учётом лимитов. Итого рабочий день. Если что-то занимает
кратно дольше — остановиться и спросить заказчика, а не жечь бюджет.

# ТЗ: добор базы «проектов клиентского масштаба» до 100 кейсов

Дата: 2026-08-27. База: data/small-cases.json, сейчас 73 кейса.
Продукт-потребитель: /projects/ (каталог кейсов) и /solutions/ (блоки «Реальные проекты»).

## 1. Зачем добор (анализ пробелов)

Текущий корпус перекошен в сторону продуктовых/IT-компаний (technology 22 +
professional-services 15 = половина базы), потому что AI-студии чаще всего делают
продукты для других технологических компаний. Целевой же клиент каталога — «обычный»
бизнес: ритейл, производство, финансы, логистика, стройка, энергетика. Именно эти
отрасли недопредставлены:

|---|---|---|---|
| retail-ecommerce | 4 | ≥9 | +5 |
| finance-insurance | 4 | ≥8 | +4 |
| logistics-transport | 3 | ≥7 | +4 |
| manufacturing | 6 | ≥9 | +3 |
| energy-utilities | 0 | ≥2 | +2 |

| technology / professional-services | 37 | квота 0 | только исключительные |

Итого: +27, целевой размер базы ≥100.

Процессные пробелы (предпочитать при равном качестве): finance-accounting (0),
pricing (1), procurement-tenders (1), quality-control/cv-inspection, supply-chain,
predictive-maintenance, hr-recruitment; механизмы: voice-agent, speech-analytics,
optimization-ml, generative-ai.

Региональный баланс: сейчас russia-cis 11/73; в доборе ≥6 русскоязычных (цель ≥17/100).

## 2. Источники и приоритет

1. **Clutch** (каркас): отраслевые срезы каталога AI-разработчиков
   (retail, financial services, logistics, manufacturing, hospitality, energy) →
   профили студий, специализирующихся на целевых отраслях; извлечение отзывов
   с бюджетом $50k–1M. Отраслевой таргетинг в промпте извлечения обязателен —
   иначе снова соберём продуктовые IT-кейсы.
2. **Русскоязычный слой**: workspace.ru/cases (поиск по отраслевым запросам:
   ритейл, логистика, производство, энергетика + ИИ/ML), Habr-блоги интеграторов,
   публичные разборы исполнителей. Бюджет «не раскрыт» допустим.
3. Профили из первой волны с непросмотренными отзывами — только при недоборе квоты.

## 3. Правила качества (без изменений + уточнения)

- Вилка бюджета $50k–1M раскрыта источником — для Clutch-кейсов обязательна;
  ниже $50k допускается только для RU-кейсов и вилки usd_10_50k НЕ вводим —
  такие кейсы получают undisclosed + budget_note при явной сумме.
- AI-содержание обязательно: rule-based боты, чистый DevOps/CRM без ML — отказ.
- Дедуп против существующих 73 (тот же проект у той же студии = отказ).
- Обезличенность: имена студий и клиентов не попадают в публичные поля;
  source.url — только во внутренней базе.
- Каждый кейс: pain (реконструкция боли) + problem + solution + result_summary,
  метрики со статусом reported, confidence client_review|vendor_report,
  поля по схеме существующих записей (валидация по таксономии, 0 ошибок).
- Сырьё каждого батча — в research/small-cases/raw/ до записи в базу.

## 4. Критерии приёмки

1. Всего ≥100 кейсов; отраслевые цели из таблицы выполнены (допуск −1 по отрасли
   при документированной нехватке материала).
2. С раскрытой бюджетной вилкой ≥72; russia-cis ≥16.
3. Валидация схемы и таксономии — 0 ошибок; дублей нет.
4. build-scale-data: 0 утечек; grep бандла по URL/площадкам чистый.
5. Чек-лист scale-ui — зелёный; /projects/ и блоки «Реальные проекты» в /solutions/
   живы; счётчики на главной каталога отражают новый объём.
6. Плановые расхождения фиксируются в этом файле постфактум (раздел «Итоги»).

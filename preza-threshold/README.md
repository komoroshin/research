# Threshold — презентация

Самодостаточная HTML-презентация: 12 слайдов плюс приложение из шести.
Открывается двойным кликом по `index.html`, работает офлайн — ни внешних
шрифтов, ни CDN, ни единого сетевого запроса. Сборки нет: HTML, CSS и один
классический скрипт.

Настоящий текст стоит в `content.js` — 12 слайдов и 6 слайдов приложения,
перенесены дословно из `preza-threshold-kontent.md`. Файл `content.example.js`
остался запасным: если `content.js` убрать, презентация откатится на него и
пометит себя надписью `example content`.

### Три места, где решение принято за пределами текста

1. **Слайд 9.** Строки вида «**Измеряют:** Function, Whoop, Oura — план, а не
   ведение» разложены в две колонки таблицы: метка слева, содержимое справа.
   Двоеточие после метки ушло в границу ячейки, слова не менялись.
2. **Слайд 4.** Подписи фаз на схеме берутся из буллетов самого слайда, а не
   зашиты в код. Иначе рисунок мог бы разойтись с текстом — в первой версии
   схема утверждала «базовый период 14 дней», тогда как в контенте «базовая
   линия 7–10 дней».
3. **Приложение.** В контент-файле шесть пунктов списка без содержимого, они
   собраны как шесть слайдов с этими строками в заголовке. Тела у них нет —
   если приложение понадобится на встрече, текст нужно дописать.

## Как править тексты

Все тексты слайдов и заметок лежат **в одном файле**, отдельно от вёрстки:

| Файл | Что это |
|---|---|
| `content.js` | Настоящий текст. Пока отсутствует. |
| `content.example.js` | Подставной текст, к которому презентация откатывается. |

Формат — размеченный текст внутри `window.DECK = String.raw\`…\``:

```
=== slide 7 | layout: arithmetic
# Заголовок слайда берётся из контента как есть
Абзац.
- пункт списка
!! строка с арифметикой — акцентный блок
| ячейка | ячейка | ячейка |
[big] 445 | оценок
> строка-подвал
--- notes
Всё после этой строки — заметки докладчика. На экран не попадает никогда.
```

Раскладки: `title`, `statement` (по умолчанию), `metric`, `phases` (слайд 4),
`arithmetic` (слайд 7), `levels` (слайд 9), `tranches` (слайд 12).
Слайды приложения объявляются как `=== appendix 1 | layout: statement`.

Из разметки внутри текста поддерживается только `**жирный**` — всё остальное
выводится буквально, чтобы выверенные формулировки нельзя было случайно
переформатировать.

**Порядок в файле не важен** — слайды сортируются по номеру в заголовке.

## Показ

| Клавиша | Действие |
|---|---|
| → ↓ Space PageDown | следующий слайд |
| ← ↑ PageUp | предыдущий |
| Home / End | первый / двенадцатый |
| цифры + Enter | переход на слайд по номеру (приложение — 13…18) |
| `A` | открыть приложение |
| `P` | открыть режим докладчика |
| `F` | полноэкранный режим |

Пролистывание с 12-го слайда **не ведёт в приложение** — показ там
заканчивается. Приложение открывается только по номеру или клавишей `A`.

### На телефоне

Клавиатуры там нет, поэтому показ листается тремя способами: свайп влево и
вправо, тап по правой или левой трети экрана, и панель `‹ 7 / 12 ›` внизу.
Тап по счётчику открывает сетку номеров — так на телефоне открывается нужный
слайд и приложение, раз номер набрать негде. Панель показывается только на
узких экранах и на устройствах без мыши: на проекторе и в PDF её нет.

Проверяется автотестом:

```bash
node touch-test.mjs           # локальная версия
node touch-test.mjs ../путь   # любая собранная копия
```

## Режим докладчика

`P` открывает отдельное окно: заметки текущего слайда (блок «Проговорить»),
миниатюра следующего слайда, таймер с момента открытия и список приложения с
номерами — чтобы во время вопроса открыть нужный слайд одним кликом.
Стрелками можно управлять и из окна докладчика.

**Заметки существуют только в этом окне.** В основном окне их нет ни в DOM, ни
в печати — это проверяется автотестом (`npm run check`).

Два окна синхронизируются через `localStorage` с опросом каждые 180 мс. Так
сделано намеренно: под `file://` браузер запрещает и обращение к свойствам
чужого окна, и запись его адреса (`SecurityError`), а хранилище работает.
Ставьте окно докладчика на ноутбук, а окно показа — на проектор в полный экран.

## Публичная копия для GitHub Pages

```bash
node make-public.mjs ../путь/к/папке
node verify-public.mjs ../путь/к/папке
```

Первая команда собирает копию **без блоков «Проговорить»**. Это не
перестраховка: заметки лежат в том же `content.js`, что и слайды, и любой, кто
откроет исходник опубликованной страницы, прочитал бы условия сделки, доли,
вестинг и строку «тракшена сегодня нет». В публичной копии их нет ни в файле,
ни в DOM, ни в окне докладчика; обеим страницам проставляется `noindex`.

Вторая команда это проверяет: считает слайды, ищет в странице характерные
куски заметок и убеждается, что окно докладчика пустое. Возвращает ненулевой
код, если что-то просочилось.

Для показа на встрече пользуйтесь локальной версией — там заметки на месте.

## PDF

Готовый файл — `threshold-deck.pdf`, **12 страниц**, один слайд на страницу,
1920×1080 без полей и обрезаний.

Приложение в PDF не входит. У его шести слайдов в контент-файле есть только
заголовки, и в присланном комитету файле они читаются как пустые страницы.
Когда у приложения появится содержимое:

```bash
npm run pdf -- --with-appendix
```

Пересобрать:

```bash
npm install     # ставит только playwright, и только ради PDF
npm run pdf
```

Скрипт печатает, сколько страниц вошло, и список слайдов, где текст не
поместился при минимальном кегле, — их размер **не подгоняется**, это правится
в тексте.

## Проверки

```bash
npm run check
```

Проходит по показу: открывается ли на первом слайде, доходят ли стрелки до
двенадцатого, не проваливается ли пролистывание в приложение, работают ли
Home/End, переход по номеру и клавиша `A`, открывается ли окно докладчика,
следует ли оно за показом, рисуется ли миниатюра — и главное, не протекают ли
заметки на основной экран.

## Типографика

Слайд — фиксированный холст 1920×1080, который масштабируется под экран
целиком. Поэтому кегли ниже точны, а не «примерно»:

| Роль | Кегль | Доля высоты слайда |
|---|---|---|
| Заголовок | 78 px (62 px для длинных) | 7,2% |
| Основной текст и списки | 34 px | 3,1% |
| Лид, вводный абзац | 40 px | 3,7% |
| Надзаголовок, подписи, таблица (первая колонка) | 26 px | **2,41% — минимум** |
| Строка арифметики (слайд 7) | 62 px | 5,7% |
| Крупное число | 150 px | 13,9% |

Требование ТЗ — не ниже 2,2% от высоты слайда; минимум в макете 2,41%.
Ниже этой границы только номер слайда (20 px) и метка подставного контента —
это служебные элементы, а не содержание.

### Где текст не поместился

**Пока нигде.** На подставном контенте `npm run pdf` сообщает: все слайды
помещаются при минимальном кегле. Прогоните проверку заново после подстановки
настоящих текстов — если появятся переполнения, они выведутся списком, и это
правится сокращением текста, а не уменьшением кегля.

## Оформление

Регистр — спокойная точность: бумажный фон, чернильный текст, один сдержанный
акцент, много воздуха, строгая сетка. Ни фотографий, ни иконок, ни градиентов,
ни теней, ни карточек со скруглениями.

Презентация намеренно выглядит как документ, который производит сам продукт, —
одностраничная сводка, которую человек уносит врачу. Единственный элемент
фирменного стиля, перенесённый из приложения, — оранжевая волосяная линия, по
одной на слайд.

Числа набираются крупно, единицы измерения — мелко рядом.

Слайд 4 — единственная графика, схема четырёх фаз, нарисованная кодом (SVG):
фазы идут слева направо по общей оси, третья выделена заливкой и состоит из
пяти повторяющихся тестов с пунктирными перерывами между ними.
